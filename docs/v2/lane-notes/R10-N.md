# R10-N

## 做了什么
config.json 的 notify.receivers[] 存在 CLI 与 serve 解析出的同一个 home。字段是 id、adapter（codex、hermes、lark、file）、target、hermes 可选 root、scope（projects、objectives、dir_prefixes 或 all:true；都空则不主动订阅，只参与 origin 解析）、events（问题种类，空为全部）、enabled。原子写入（临时文件再 rename），保留其它键和未知字段。非法条目跳过，警告写出条目和原因，其余条目仍加载，加载不因 receivers 失败。未知 notify 键仍警告；fallback 与 receivers 不警告。
cardex notify add|list|remove|test。add 接受全部字段。--from-origin 使用 --origin，否则 CARDEX_ORIGIN：codex:<thread> 成为 codex，hermes:<profile>/<session> 成为 hermes。重复 id 报错且不改文件。list 列出每个接收者和 enabled 或 disabled。remove <id> 删除该条。test <id> 发送一条；hermes 先打印 <wake>.ack.json 路径，再在有限等待内看到 ack 才报告 received。
投递顺序是 origin、scope 命中的 enabled 接收者、notify.fallback、inbox，按地址去重。events 只作用于 scope 接收者。hermes:<profile>/<session> 的订阅 id 来自 enabled hermes 接收者：一个 session 命中优先于 profile；没有命中或不唯一则跳过这一跳并记一条事件（缺订阅 id、hermes session 匹配不唯一、hermes profile 匹配不唯一），fallback、inbox 和其它目标仍投。root 非空时写到 <root>/control/manager-wake/hermes-inbox/<id>/，否则用本次 home。入站和 ack 字段保持现有 hermes 格式。ack 把该跳标成已送达；没有 ack 沿用原来的提醒间隔，不新增重试。
import-legacy 只读 v1 <home>/config.json 的 manager_wake.subscriptions。provider→adapter。codex 的 target 取 thread_id，否则 profile。hermes 在 profile 和 thread_id 都有时写成 profile/thread_id。projects 与 dir_prefixes 保留。task_ids 映射为导入目标 id v1-import-<project>，找不到的记入 Notes。event_types：done→done；needs_owner、held、failed→freeze、reopen、breaker、budget、refusal、custom；canceled 无 v2 通知并记入 Notes。仅含无法映射的事件时不写入接收者。enabled 保留。已存在的 id 不覆盖并记入 Notes。v1 源不修改。

## 没做什么，以及原因
没有改 Hermes 或 Agent 运行时。没有 v1 outbox.jsonl，没有飞书卡片。没有新表、新模块依赖、新问题种类。lark 与 file 的投递函数没有改道。没有改 design.md、internal/model、internal/store/migrate.go、go.mod、internal/sched/loop.go。
